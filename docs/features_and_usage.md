# 🌟 核心特性与使用手册 (Features & Usage)

本文档详细介绍了本商业激活系统中最新引入的高级功能及其使用方法。这些特性能够帮助您更好地进行自动化集成、测试管理以及系统安全防御。

---

## 1. 🪝 Webhooks 自动化通知系统

为了方便系统与您的第三方工具（如企业微信、钉钉机器人、Slack 或外部 ERP 系统）进行集成，系统内置了强大的 Webhook 机制。

### 1.1 支持的事件类型
系统当前支持在以下关键节点触发 Webhook：
- **授权颁发 (`LicenseGenerated`)**: 当管理员在后台成功批量生成激活码时触发。
- **设备激活 (`DeviceActivated`)**: 当终端用户成功绑定或换绑设备时触发。
- **设备解绑 (`DeviceDeactivated`)**: 当设备被手动解绑或触发自动换绑逻辑时触发。

### 1.2 配置方法
1. 在生产环境的 `.env` 文件中配置 `WEBHOOK_URL` 变量。
2. 确保 `WEBHOOK_SECRET` 已配置（用于计算哈希签名）。
3. (可选) 配置 `WEBHOOK_ENABLED=true` 以开启。

### 1.3 请求体结构 (Payload)
系统会向目标 URL 发送 `POST` 请求，Header 中会携带 `X-Signature`（使用 HMAC-SHA256 对请求体签名），以确保数据来源的合法性。
```json
{
  "event": "DeviceActivated",
  "timestamp": "2026-08-18T10:30:00Z",
  "data": {
    "licenseKeyHash": "5A4B...",
    "hardwareId": "HW-CPU-123456",
    "ipAddress": "192.168.1.100"
  }
}
```

## 2. 🔑 Admin API Keys (API 密钥管理)

在 B2B2C 商业模式下，您可能需要通过外部自动发卡商城（如发卡网、自建电商）自动调用本系统的接口来生成激活码。为了取代不安全的密码自动登录，系统引入了专门用于程序调用的 **API Key** 机制。

### 2.1 如何生成和使用
1. 超级管理员登录系统后台面板 (`/admin`)。
2. 进入“API 密钥”管理模块，点击“生成新密钥”。
3. 复制生成的明文 Key。**（请妥善保管，关闭窗口后将无法再次查看）**。
4. 将该 Key 用于外部系统的 HTTP 接口调用。

### 2.2 接口鉴权方式
外部商城在调用 `/api/admin/generate-license` 接口时，只需在 HTTP 请求头中带上：
```http
X-Api-Key: 您生成的API_KEY
```
系统将会自动对该操作进行审计记录，并将其标记为 API 调用。

## 3. 🧪 商业测试模式 (Test Activation)

在系统正式投入运营前，您需要测试生成、激活、吊销的全流程。为了避免测试数据污染正式的控制台面板，系统引入了物理隔离的测试机制。

### 3.1 专属测试页面
访问 `/test-activation` 即可进入测试专用面板。该面板提供了：
- **模拟激活**: 自动采集当前浏览器环境的伪装机器码进行激活请求。
- **强制重置**: 允许无视限制，清零某个测试激活码的激活次数（正式服此接口将被严格封禁）。
- **设备解绑**: 一键将已绑定的测试设备移除。

### 3.2 `TEST-` 机器码隔离机制
通过 `/test-activation` 面板发起的所有硬件 ID 都会被自动打上 `TEST-` 前缀（例如：`TEST-3558ec55-6e4a...`）。
系统后台在进行数据分析和设备列表展示时，默认将此类测试设备进行**红色高亮**或过滤处理，确保您的商用运营大盘不受测试干扰。

## 4. 🔏 离线签名与验证 (Offline RSA/Ed25519 Verification)

为了彻底根绝终端破解者通过篡改本地系统时间、修改本地验证逻辑来破解授权期的可能性，系统采用了金融级别的非对称数字签名。

### 4.1 签名发放机制
终端调用 `/api/license/activate` 成功后，服务端使用强加密私钥对“硬件ID + 激活码 + 过期时间”这三个要素进行数字签名，并以 Base64 格式返回。

### 4.2 C端接入规范
您的桌面客户端软件在本地接收到数据后，必须：
1. **严禁**直接信任明文 JSON 中的过期时间。
2. 将返回的 `Signature` 签名串使用随软件打包的**公钥**（Public Key）进行本地验签。
3. 如果签名被篡改，或用户强行将系统时间修改至有效期内，但签名校验不通过，应立即闪退或弹窗报错。

这种机制下，黑客除非拿到部署在您服务器深处的私钥，否则无法伪造任何有效的激活回执。
